01 · สภาพปัญหา
ปัญหาที่เราเจอทุกวัน
ก่อนมีระบบ NBC STOCK
📋

จดบันทึกด้วยมือ

บันทึกการรับเข้า-ตัดจ่ายลงสมุด/กระดาษ ข้อมูลกระจัดกระจาย ค้นหาย้อนกลับยาก สูญหายได้ง่าย

🔍

ค้นหา Lot ได้ยาก

ต้องพลิกสมุดทีละหน้าเพื่อหา Lot Number หรือตรวจสอบสถานะ QC ใช้เวลา 10-15 นาทีต่อครั้ง

⚠️

ไม่รู้ว่าของใกล้หมด

ไม่มีระบบแจ้งเตือนเมื่อพัสดุใกล้หมดคลัง ทำให้สั่งซื้อไม่ทัน กระทบการส่งมอบงาน

📞

เคลม NCP ตกหล่น

ไม่มีระบบติดตามการเคลมสินค้าที่ไม่ผ่าน QC มีเคสที่เลยกำหนดติดตามโดยไม่รู้ตัว

📊

ไม่มีข้อมูลวิเคราะห์

ไม่สามารถดูภาพรวมสต็อก หรือวิเคราะห์แนวโน้มการใช้พัสดุได้เลย

📑

ทำรายงานช้า

สรุปรายงานเพื่อ audit ต้องรวบรวมจากหลายแหล่ง ใช้เวลาหลายชั่วโมง

02 · วัตถุประสงค์
เราจะแก้ปัญหาอย่างไร

🎯 วัตถุประสงค์หลัก

  • พัฒนาระบบบริหารคลังพัสดุแบบดิจิทัล ทดแทนการจดด้วยมือ
  • ลดเวลาการค้นหาและตรวจสอบข้อมูลพัสดุ
  • สร้างระบบแจ้งเตือนอัตโนมัติเมื่อพัสดุใกล้หมดคลัง
  • สร้างระบบติดตามการเคลม NCP อย่างเป็นระบบ
  • รองรับการออกรายงานและส่งออก Excel ได้ทันที

💡 แนวคิดหลัก

  • ต้นทุนเป็นศูนย์ — ใช้เทคโนโลยี Open Source ไม่มีค่า License
  • ออกแบบจาก Pain Point จริง — ไม่ซื้อสำเร็จรูป
  • ใช้ได้ทุกอุปกรณ์ — Web App เปิดได้ทั้งคอม แท็บเล็ต มือถือ
  • ซิงค์ข้ามเครื่อง — Cloud Sync ผ่าน Firebase

📐 ตัวชี้วัด (KPI)

  • ลดเวลาค้นหาพัสดุ ≥ 80%
  • ลดเคส NCP ที่ตกหล่น = 0 เคส
  • ลดเวลาจัดทำรายงาน ≥ 70%
  • ความพึงพอใจผู้ใช้งาน ≥ 80%
02 · วิธีการดำเนินงาน
วงจรคุณภาพ PDCA
P

Plan — วางแผน

สำรวจปัญหาการจัดการคลังพัสดุ รวบรวม pain points จากผู้ใช้จริง กำหนด requirement และตัวชี้วัด ออกแบบ workflow

D

Do — ลงมือทำ

พัฒนาระบบ NBC STOCK ด้วย React + Firebase ทดสอบกับผู้ใช้จริง ปรับปรุงตาม feedback เช่น เพิ่ม filter, multi-item สัญญา

C

Check — ตรวจสอบ

วัดผลเทียบกับ KPI ที่ตั้งไว้ เก็บ feedback ความพึงพอใจผู้ใช้ ตรวจสอบว่าปัญหาเดิมถูกแก้ไขได้จริง

A

Act — ปรับปรุง

ปรับปรุงระบบต่อเนื่องจาก feedback เช่น เพิ่มระบบพิมพ์ป้ายสถานะ วิเคราะห์ stock วางแผน roadmap เฟสถัดไป

02 · ความสอดคล้อง
สอดคล้องกับเกณฑ์ 3S + 1E
🛡️

Safety

ระบบ QC Status Tracking ป้องกันพัสดุที่ไม่ผ่าน QC หลุดเข้าสู่กระบวนการใช้งาน ลดความเสี่ยงด้านคุณภาพ

😊

Satisfaction

ผู้ใช้ค้นหาข้อมูลได้เร็วขึ้น ลดภาระงานซ้ำซ้อน มี Dashboard ภาพรวมที่ชัดเจน ทำงานสะดวกขึ้น

📏

Standard

สร้างมาตรฐานในการบริหารคลังพัสดุ ตั้งแต่รับเข้า ตรวจ QC จัดเก็บ ตัดจ่าย และเคลม ผ่านระบบเดียวกัน

🌿

Environment

ลดการใช้กระดาษจากการจดบันทึกและพิมพ์รายงาน เปลี่ยนเป็นดิจิทัลทั้งหมด สภาพแวดล้อมการทำงานดีขึ้น

03 · ฟีเจอร์เด่น
Dashboard ภาพรวมอัจฉริยะ

🔔 ระบบแจ้งเตือนอัตโนมัติ

  • พัสดุใกล้หมด — คำนวณจากอัตราการใช้จริง พยากรณ์ว่าจะหมดภายในกี่วัน
  • พัสดุหมดคลัง — รายการที่ต้องสั่งซื้อเร่งด่วน

  • Quarantine ค้าง — พัสดุรอ QC กี่รายการ

  • รายการรับเข้าล่าสุด 5 รายการ
  • กำหนดติดตามงานเคลมที่ใกล้ถึง

03 · ขั้นตอนการทำงาน
Workflow ครบวงจร

📥 รับเข้า

บันทึกพัสดุพร้อม Lot, วันผลิต, วันหมดอายุ, ผู้ส่ง, จำนวน, เอกสาร

🔬 ตรวจ QC

กำหนดสถานะ Pass / Quarantine / Reject พร้อมพิมพ์ป้ายติดพัสดุ

📤 ตัดจ่าย

เบิกจ่ายพัสดุ ระบุผู้เบิก แผนก วัตถุประสงค์ ตัดยอดอัตโนมัติ

⚠️ เคลม NCP

พัสดุ Reject สร้างเคสเคลม/คืน พร้อมกำหนดวันติดตาม

💡

จุดเด่น: ข้อมูลเชื่อมโยงกันอัตโนมัติ

รับเข้าพัสดุ → ยอดในคลังอัปเดตทันที → ตัดจ่ายหักยอดอัตโนมัติ → Reject สร้างเคส NCP ได้เลย → Dashboard แจ้งเตือนทั้งหมด

04 · ตัวชี้วัด
ผลลัพธ์ที่ วัดได้จริง
เปรียบเทียบก่อนและหลังนำระบบไปใช้งาน
ตัวชี้วัด (KPI) ก่อน (Before) หลัง (After) ผลลัพธ์
เวลาค้นหาพัสดุ/Lot 10-15 นาที < 10 วินาที ↓ ลดลง > 98%
เคลม NCP ที่ตกหล่น/เลยกำหนด ไม่มีการติดตาม 0 เคส (มีแจ้งเตือน) ✓ แก้ปัญหาได้ 100%
เวลาจัดทำรายงาน 2-3 ชั่วโมง 30 วินาที ↓ ลดลง > 99%
ต้นทุนค่าซอฟต์แวร์ — 0 บาท ฟรี 100%
การเข้าถึงข้อมูลข้ามอุปกรณ์ ไม่ได้ Real-time Sync ✓ ทุกเครื่องเห็นข้อมูลเดียวกัน
ความพึงพอใจผู้ใช้งาน ยังไม่เคยวัด [รอเก็บข้อมูล] เป้าหมาย ≥ 80%
💡 หมายเหตุ: ตัวเลขที่เป็น [รอเก็บข้อมูล] ควรเก็บจริงก่อนวันนำเสนอ
05 · แผนพัฒนาต่อยอด
Roadmap ความยั่งยืน
ระบบสามารถพัฒนาต่อยอดได้อีกมาก

เฟส 1 (ปัจจุบัน ✅)

ระบบหลักครบ: รับเข้า, คลัง, ตัดจ่าย, เคลม, สัญญาจัดซื้อ, Excel Export, Cloud Sync

เฟส 2

เพิ่มระบบ Login/Permission, Barcode Scanning, Line Notification

เฟส 3

BI Dashboard ขั้นสูง, รายงานอัตโนมัติ, เชื่อมต่อระบบจัดซื้อกลาง

เฟส 4

ขยายไปใช้กับหน่วยงานอื่น, Mobile App, AI Forecasting

✅ ทำไมจึงยั่งยืน

  • Open Source — ซอร์สโค้ดอยู่บน GitHub ใครก็มาพัฒนาต่อได้
  • ใช้เทคโนโลยีที่แพร่หลาย (React) — หาคนดูแลไม่ยาก
  • ต้นทุนดำเนินงาน = 0 บาท ไม่มีภาระรายเดือน
  • Scale ไปใช้กับหน่วยงานอื่นได้โดยไม่ต้องลงทุนเพิ่ม

🔄 การถ่ายทอดความรู้

  • จัดทำคู่มือการใช้งานสำหรับผู้ใช้
  • จัดอบรมให้ทีมงานที่เกี่ยวข้อง
  • โค้ดมี comment อธิบายเป็นภาษาไทย
  • เผยแพร่เป็น best practice ให้หน่วยงานอื่น
